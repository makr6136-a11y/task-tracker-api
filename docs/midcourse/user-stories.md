## Feature 1: Due Dates + Overdue Filter

| ID | Story | Acceptance Criteria | Notes / Assumptions |
|---|---|---|---|
| DD-1 | As a team member, I want to set an optional due date when creating or editing a task so that I know when it needs to be completed. | 1. The task form includes an optional "Due Date" field that accepts a date value (e.g., YYYY-MM-DD).<br>2. If left blank, the task is saved successfully with no due date set.<br>3. If a due date is provided, it is saved and displayed correctly on the task detail/list view. | Assumes date-only granularity (no time-of-day component) unless otherwise specified. |
| DD-2 | As a team member, I want the system to reject invalid or malformed due dates so that task data stays accurate and consistent. | 1. Submitting a due date in an invalid format (e.g., "13/45/2026" or non-date text) returns a validation error and does not save the task.<br>2. The error message clearly indicates the expected date format.<br>3. Existing task data is left unchanged if an edit submission fails validation. | Covers the required failure-case scenario; assumes client and/or server-side validation against a single accepted date format. |
| DD-3 | As a team member, I want tasks that are past their due date to be visually flagged as overdue so that I can quickly identify work that needs attention. | 1. Any task with a due date earlier than the current date, and a status other than "Done," is marked as "Overdue" in the task list (e.g., label, icon, or highlight).<br>2. Tasks with status "Done" are never shown as overdue, regardless of due date.<br>3. Tasks with no due date are never marked overdue. | Assumes "current date" is the server/system date; no timezone handling beyond a single default. |
| DD-4 | As a team member, I want to filter the task list to show only overdue tasks so that I can prioritize what's late. | 1. An "Overdue" filter option is available alongside existing status/priority filters.<br>2. Applying the overdue filter returns only tasks meeting the overdue criteria defined in DD-3.<br>3. The overdue filter can be combined with existing status and priority filters without errors. | Builds on, but does not duplicate, the existing filter feature; only adds the new overdue criterion. |
| DD-5 | As a team member, I want to update or remove a task's due date after it's created, so that I can adjust deadlines as plans change. | 1. `PATCH` on an existing task accepts a new due date value and updates it correctly.<br>2. Submitting an invalid due date format on update returns a validation error and leaves the existing due date unchanged.<br>3. A due date can be explicitly cleared (set back to no due date), and the task correctly stops being flagged as overdue if applicable. | **Corrected AI assumption:** The original AI-generated DD-5 proposed sorting tasks by due date, which was outside the original feature scope (only creation, validation, overdue flagging, and filtering were requested — no sorting). This was replaced with a story covering updating/clearing a task's due date via PATCH, which is directly in scope and mirrors the existing update pattern already used for other task fields. |

## Feature 2: Search + Combined Filters

| ID | Story | Acceptance Criteria | Notes / Assumptions |
|---|---|---|---|
| S1 | As a team member, I want to search tasks by keyword so that I can quickly find a task without scrolling through the full list. | 1. Entering a keyword returns only tasks where the keyword appears in the title and/or description (case-insensitive).<br>2. Results update to show the matching task list after a search is submitted/typed.<br>3. Clearing the search box restores the full unfiltered task list. | Assumes search is substring match, not fuzzy/full-text search, unless otherwise specified. |
| S2 | As a team member, I want my keyword search to combine with the existing status filter so that I can narrow results to only relevant tasks. | 1. When both a keyword and a status filter are applied, only tasks matching both conditions are shown.<br>2. Changing the status filter while a keyword is active re-applies the keyword search to the new filtered set.<br>3. Removing the status filter reverts to keyword-only results. | Assumes status filter behaves as an AND condition with search, not OR. |
| S3 | As a team member, I want my keyword search to combine with the existing priority filter so that I can find high-priority (or other priority) tasks matching a term. | 1. When both a keyword and a priority filter are applied, only tasks matching both conditions are shown.<br>2. Search + priority filter can be combined with status filter simultaneously (all three together) with correct AND logic.<br>3. Toggling the priority filter on/off updates results without needing to re-enter the keyword. | Confirms all filters (status, priority, search) compose together, since spec says "combinable with existing filters." |
| S4 | As a team member, I want to see a clear message when my search and filters return no matches so that I understand there are no results rather than assuming the app is broken. | 1. When a keyword/filter combination matches no tasks, `GET /tasks` returns `200` with an empty array `[]` — not an error status.<br>2. The frontend displays an explicit "no tasks found" (or equivalent) message when it receives an empty list, instead of an empty/blank board.<br>3. Adjusting or clearing the search/filters after a no-results state correctly re-displays matching tasks if any exist. | **Corrected AI assumption:** The original AI-generated S4 focused only on the frontend "no results" messaging, leaving an implicit and unstated assumption about the underlying API contract. This was corrected to explicitly require that `GET /tasks` returns `200` with an empty array `[]` for no matches — matching the project's established pattern already used in `test_list_tasks_empty_returns_200_and_empty_list` — rather than treating "no results" as an error condition. |
| S5 | As a team member, I want the search to handle empty, whitespace-only, or special-character input gracefully so that it doesn't error out or return unexpected results. | 1. Submitting an empty or whitespace-only search term is treated as no keyword filter (returns all tasks, subject to any active status/priority filters).<br>2. Special characters (e.g., %, _, *, quotes) in the search box do not cause a server error and are treated as literal text to match.<br>3. Leading/trailing whitespace in the search term is trimmed before matching. | Assumes no wildcard/regex syntax is supported in search input; edge case/failure handling per requirement.
